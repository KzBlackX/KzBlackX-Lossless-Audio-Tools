# 在腾讯云 VPS 上部署 KzBlackX（与 TeamSpeak 6 共存）

面向你当前这台机器：

| 项目 | 值 |
|---|---|
| 云服务器 | 腾讯云 OpenCloudOS 9.6 / x86_64 / 2 核 / 956 MB / 40 GB |
| 公网 IP | `124.220.202.166` |
| 内网 IP | `10.0.0.4`（公网是 1:1 NAT，必须告诉 KzBlackX） |
| EasyTier IP | `10.0.0.10` |
| 已有服务 | TeamSpeak 6 beta（语音 UDP 9987、文件 TCP 30033） |
| 带宽 | 200 Mbps |

KzBlackX 和 TS6 **不冲突**：TS6 用 9987/UDP，KzBlackX 用 3478/UDP + 一个 HTTPS 端口。两个可以同时跑，内存上也放得下（KzBlackX 空闲约 16 MB）。

建议分配一个子域名，例如：

```
voice.kzblackx.net  A  124.220.202.166
```

不要复用 `ts.kzblackx.net`，否则以后想换端口或换机器会互相影响。

---

## 0. 先决定 HTTPS 怎么给

浏览器只在 HTTPS（或 localhost）下允许麦克风，所以公网访问必须有证书。三种做法，按你的环境选一个：

| 方案 | 适用 | 端口 |
|---|---|---|
| **A. 内置 ACME** | 80/443 空闲，域名已备案 | TCP 80、443 |
| **B. 宝塔现成证书 + 高位端口** | 443 被宝塔/网站占用，或未备案 | TCP 8443（示例） |
| **C. 宝塔反向代理** | 想复用宝塔的 443 和证书 | TCP 443 + 本机 8080 |

> 中国大陆节点的域名走 80/443 通常要求 ICP 备案。没备案就选 B（8443）最省事；证书可以让宝塔申请，DNS 验证不需要 80 端口。

下面以 **方案 B** 为主，A/C 在文末给出差异。

## 1. 上传并安装

在本地把二进制传上去（假设你已经能 SSH 到 `124.220.202.166`）：

```bash
scp dist/kzblackx-audio-linux-amd64 root@124.220.202.166:/root/kzblackx-audio-linux-amd64
scp -r deploy root@124.220.202.166:/root/kzblackx-deploy
```

登录服务器：

```bash
ssh root@124.220.202.166
```

先确认端口空闲：

```bash
ss -lntup | grep -E ':(8443|3478)\b' || echo "端口空闲"
```

安装：

```bash
cd /root
ADDR=:8443 \
PUBLIC_IP=124.220.202.166 \
PASSWORD="$(openssl rand -hex 16)" \
./kzblackx-deploy/install.sh ./kzblackx-audio-linux-amd64
```

脚本会打印**服务器密码**，记下来发给朋友。配置在 `/etc/kzblackx/audio.env`。
这里没有传 `DOMAIN`，所以不会自动启用 ACME，适合 443 已被宝塔占用的情况；如果 80/443 空闲、想用内置证书，见文末「方案 A」。

因为示例用了 8443 + 证书文件，先编辑配置：

```bash
vi /etc/kzblackx/audio.env
```

加上（把域名换成你的实际域名）：

```ini
KZBX_ADDR=:8443
KZBX_TLS_CERT=/www/server/panel/vhost/cert/voice.kzblackx.net/fullchain.pem
KZBX_TLS_KEY=/www/server/panel/vhost/cert/voice.kzblackx.net/privkey.pem
KZBX_PUBLIC_IP=124.220.202.166
```

> 如果文件里已经有 `KZBX_ACME_DOMAIN=` 这一行，请删掉：内置 ACME 与证书文件互斥，同时存在会启动失败。
> 证书路径以宝塔实际为准，常见位置：
> `/www/server/panel/vhost/cert/<域名>/fullchain.pem` 与 `privkey.pem`。
> 如果证书还没申请：宝塔 → 网站 → 添加站点（纯静态即可）→ SSL → Let's Encrypt → **DNS 验证**。

重启并看日志：

```bash
systemctl restart kzblackx-audio
systemctl status kzblackx-audio --no-pager
journalctl -u kzblackx-audio -n 30 --no-pager
```

正常会看到：

```
level=INFO msg="https listening" addr=:8443
level=INFO msg="media endpoint ready" udp_port=3478 public_ip=124.220.202.166
```

## 2. 放行端口

腾讯云控制台 → 轻量应用服务器/云服务器 → **防火墙 / 安全组**，入站放行：

| 协议 | 端口 | 来源 | 用途 |
|---|---|---|---|
| TCP | 8443 | 0.0.0.0/0 | 页面 + WebSocket |
| UDP | 3478 | 0.0.0.0/0 | 语音媒体 |

如果用内置 ACME，再加 TCP 80；如果用 443，改成 443。**不要**把 UDP 3478 配成 HTTP 反向代理。

主机防火墙（OpenCloudOS 一般用 firewalld）：

```bash
firewall-cmd --permanent --add-port=8443/tcp
firewall-cmd --permanent --add-port=3478/udp
firewall-cmd --reload
firewall-cmd --list-ports
```

宝塔面板如果开了系统防火墙，也可以在「安全」里加同样的规则。

## 3. 验证

### 3.1 服务端

```bash
curl -k -s https://127.0.0.1:8443/healthz
# {"ok":true,"peers":0,"rooms":3,"uptime":12,"version":"0.1.0"}

ss -lunp | grep 3478
# UNCONN 0 0 0.0.0.0:3478 ... users:(("kzblackx-audio",pid=...,fd=...))
```

从**另一台机器**（不要用服务器本机）验证：

```bash
curl -s https://voice.kzblackx.net:8443/healthz
```

### 3.2 浏览器

1. 打开 `https://voice.kzblackx.net:8443`；
2. 输入昵称、服务器密码，登录后停在空房间页；
3. 左侧房间列表第一次点击确认，第二次点击进入（带锁房间需要房间密码）；允许麦克风；
4. 聊天框回形针发文件；控制栏显示器按钮共享桌面（帧数/分辨率/码率可选）；
5. 再开一个无痕窗口 / 手机，用同一个密码登录；
5. 双方应能互相听到，顶部显示 RTT，左下角显示服务端 RSS 与 CPU。

如果页面能开、能进房间，但双方都听不到，99% 是 **UDP 3478 没放行** 或 **`KZBX_PUBLIC_IP` 没填**。看服务端日志有没有 `public_ip=`。

### 3.3 快速看服务端状态

```bash
curl -s https://voice.kzblackx.net:8443/api/info | python3 -m json.tool | head -30
```

`stats.rssBytes` 是当前常驻内存，`stats.cpu` 是最近一个采样窗口的 CPU 百分比（单核为 100%）。

## 4. 容量与带宽

SFU 的出口流量公式：

```
出口 ≈ 人数 × (人数 − 1) × 码率
```

| 场景 | 出口带宽 | 占 200 Mbps |
|---|---|---|
| 8 人，标准 96 kbps | ≈ 5.4 Mbps | 2.7% |
| 12 人，标准 96 kbps | ≈ 12.7 Mbps | 6.3% |
| 16 人，标准 96 kbps | ≈ 23 Mbps | 11.5% |
| 8 人，录音室 320 kbps | ≈ 17.9 Mbps | 9% |
| 16 人，录音室 320 kbps | ≈ 71.7 Mbps | 36% |

- 2 核 1 GB：日常 8–12 人 96 kbps 很轻松；16 人建议实测 CPU 与出口。
- 320 kbps 档对服务端 CPU 的影响主要来自包量而非解码（服务端不编码），但每人每路字节数更大，出口更高。
- 如果按流量计费：8 人 96 kbps 挂机 1 小时约 2.4 GB 出口；320 kbps 约 8 GB/小时。

可在 `/etc/kzblackx/audio.env` 调：

```ini
KZBX_MAX_ROOM=16
KZBX_MAX_BITRATE=320
KZBX_FILES_DIR=/var/lib/kzblackx/files
KZBX_MAX_FILE_MB=100
KZBX_FILE_TTL=24h
```

## 5. 和 TeamSpeak 6 共存

| | TS6 | KzBlackX |
|---|---|---|
| 语音端口 | UDP 9987 | UDP 3478 |
| 其他端口 | TCP 30033 | TCP 8443 |
| 常驻内存 | 约 35 MB | 16–35 MB |
| 开机自启 | Docker restart | systemd |

两者可以同时在线。956 MB 内存下跑 TS6 + KzBlackX + 宝塔仍然宽裕，但如果你还跑数据库/网站，建议观察 `free -m`，必要时把 swap 保持在 1–2 GB。

如果 TS6 将来不用了，直接 `docker stop teamspeak-server && docker rm teamspeak-server`，不影响 KzBlackX。

EasyTier 网内的设备也可以直接访问 KzBlackX，但**麦克风仍然要求 HTTPS 域名**；用 `https://voice.kzblackx.net:8443` 即可，不必走 EasyTier。若想完全内网，也可以给 `10.0.0.10` 配自签证书，但浏览器会警告，不推荐发给朋友。

## 6. 方案 A：内置 ACME（80/443 空闲时）

```ini
KZBX_ACME_DOMAIN=voice.kzblackx.net
KZBX_ACME_EMAIL=you@example.com
KZBX_PUBLIC_IP=124.220.202.166
# 不要同时设置 KZBX_TLS_CERT / KZBX_TLS_KEY / KZBX_ADDR
```

放行 TCP 80、443，UDP 3478：

```bash
systemctl restart kzblackx-audio
journalctl -u kzblackx-audio -f
```

首次启动会自动申请证书，证书缓存在 `/var/lib/kzblackx/.acme-cache`。80 端口必须能从公网访问，否则 HTTP-01 校验失败。

## 7. 方案 C：宝塔反向代理（复用 443）

KzBlackX 只监听本机：

```ini
KZBX_ADDR=127.0.0.1:8080
KZBX_PUBLIC_IP=124.220.202.166
KZBX_TRUST_PROXY=1
```

宝塔 → 网站 → 设置 → 反向代理：

- 目标 URL：`http://127.0.0.1:8080`
- 发送域名：`$host`
- 开启 **WebSocket 支持**（宝塔的“反向代理”里有开关）

或者手写 nginx：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 3600s;
}
```

浏览器访问 `https://voice.kzblackx.net`，UDP 3478 仍然直连服务器。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面打不开 | 安全组/防火墙未放行 TCP | 放行 8443 或 443 |
| 能进房间但没声音 | UDP 3478 未放行 | 安全组 + firewalld 都检查 |
| 能进房间但双方都听不到 | `KZBX_PUBLIC_IP` 为空或填错 | 填公网 IP，重启 |
| 只有一个人听不到 | 对方麦克风被浏览器拒绝 / 系统静音 | 看对方页面提示与系统输入设备 |
| 手机能进但没声 | iOS 静音键/后台限制 | 关闭静音键，保持前台 |
| 顶部一直“连接中” | WebSocket 被代理拦截 | 开启 Upgrade/Connection 头，`KZBX_TRUST_PROXY=1` |
| `systemctl status` 显示 443 绑定失败 | 端口被 nginx/宝塔占用 | 换 8443，或改用反向代理 |
| 登录提示“服务器密码不正确” | 环境文件里 `KZBX_PASSWORD` 与输入不一致 | `grep PASSWORD /etc/kzblackx/audio.env` 后重启 |
| 进入房间提示“房间密码不正确” | 房主创建时设置的密码不对 | 向房主要密码；密码只在创建时设置 |
| 日志报 `listen UDP 3478: address already in use` | 端口被别的进程占用 | `ss -lunp \| grep 3478` 找到并处理 |

排障命令：

```bash
journalctl -u kzblackx-audio -f
ss -lntup | grep -E ':(8443|3478)\b'
curl -k -s https://127.0.0.1:8443/healthz
curl -s https://voice.kzblackx.net:8443/api/info
```

## 9. 日常维护

```bash
# 改配置
vi /etc/kzblackx/audio.env
systemctl restart kzblackx-audio

# 升级：替换二进制
install -m 0755 kzblackx-audio-linux-amd64 /usr/local/bin/kzblackx-audio
systemctl restart kzblackx-audio

# 看实时日志
journalctl -u kzblackx-audio -f

# 彻底卸载（保留配置）
systemctl disable --now kzblackx-audio
rm -f /usr/local/bin/kzblackx-audio /etc/systemd/system/kzblackx-audio.service
systemctl daemon-reload
```

KzBlackX 没有数据库，升级和回滚都不涉及数据迁移；唯一的“状态”是 `/etc/kzblackx/audio.env` 和 ACME 证书缓存。

## 10. 给朋友分发

把这两个东西发过去即可：

```
地址：https://voice.kzblackx.net:8443
密码：<install.sh 打印的那串>
```

朋友用 Chrome / Edge / Safari 打开，输入服务器密码和昵称后会停在空房间页，左侧列表里点两次同一房间进入。也可以把带房间参数的链接发出去：

```
https://voice.kzblackx.net:8443/?room=游戏
```

如果邀请的房间是公开的，登录后左侧会选中它并显示确认条，再点一次进入；锁定房间需要再输入房间密码。新房间用左侧 `+` 创建；空的自建房间 6 小时后自动回收，密码也随之失效。
