# 局域网 / 手机访问

## 为什么 http://IP:8099 打不开

KzBlackX 默认只监听本机：

```bash
--addr 127.0.0.1:8099
```

`127.0.0.1` 只接受**这台机器自己**的连接，同一 Wi-Fi 下的手机、平板、另一台电脑都连不进来。必须监听 `0.0.0.0`：

```bash
--addr 0.0.0.0:8443
```

## 为什么不能直接用 http

浏览器规定：麦克风只在 **HTTPS** 或 **localhost** 下可用。
用 `http://192.168.5.139:8099` 打开，页面能显示，但点“进入语音”会提示无法使用麦克风（或只能选“只听”）。

所以局域网测试也要 HTTPS。用项目自带的脚本生成一张局域网证书：

```bash
cd /vol3/DSH-Workspace/Lossless-Audio-Tools/kzblackx-audio
./deploy/make-lan-cert.sh 192.168.5.139

./dist/kzblackx-audio-linux-amd64 \
  --addr 0.0.0.0:8443 \
  --udp-port 3478 \
  --tls-cert lan-cert/lan.crt \
  --tls-key  lan-cert/lan.key \
  --password 'demo1234' \
  --rooms '大厅,游戏,音乐'
```

然后在手机/电脑打开：

```
https://192.168.5.139:8443
```

服务器密码 `demo1234`。打开后输入你的名字和这个密码，进入空房间页；左侧房间列表点第一次确认、第二次进入，点 `+` 创建新房间。

> 证书里的 IP 必须和访问地址一致。换了局域网 IP 或从 `192.168.5.139` 改成 `fnOS.local`，都要重新生成证书，或在 SAN 里同时加上。

## 证书警告怎么过

这是自签证书，浏览器会拦一次：

- **Chrome / Edge（电脑）**：高级 → 继续前往 192.168.5.139（不安全）
- **Android Chrome**：高级 → 继续前往
- **iPhone Safari**：显示详细信息 → 访问此网站 → 访问网站
- **Firefox**：高级 → 接受风险并继续

点过之后，同一主机和端口上的 `wss://` 也会被放行。页面顶部地址栏会显示“不安全”，但 `isSecureContext` 为 true，麦克风可用。

> iOS Safari 对不受信任的证书比较严格。如果点了“继续”仍然拿不到麦克风，建议用 Android/Chrome 先测，或改用一张受信任的证书（见文末）。

## 还是打不开？

按顺序排查：

### 1. 确认服务器在监听所有网卡

```bash
ss -lntup | grep -E ':(8443|3478|34780)'
```

应该看到 `*:8443` 或 `0.0.0.0:8443`，而不是 `127.0.0.1:8443`。UDP 端口也应绑定在 `0.0.0.0`。

### 2. 确认设备在同一个网段

在手机/另一台电脑上：

```bash
ping 192.168.5.139
```

- 不通：设备可能连的是访客 Wi-Fi、另一个 VLAN/子网，或者路由器开了 **AP 隔离**；也可能 fnOS 的防火墙拦了端口。
- 通但端口不通：检查 fnOS 的防火墙/安全设置，放行 TCP 8443 和 UDP 34780（或你实际用的端口）。
- 用 `curl -k https://192.168.5.139:8443/healthz` 能返回 JSON，就说明网络和证书层都通了。

### 3. 页面能开，但进不去房间

- 看页面提示：服务器密码错误 / 房间密码错误 / 房间满 / 连接超时。
- 看服务端日志：`journalctl -u kzblackx-audio -f` 或启动它的终端。
- 用 `--log-level debug` 启动，能看到 `peer joined`、`publishing audio`、`first rtp packet`。

### 4. 能进房间，但听不到

- 双方都要在同一个房间（登录后在左侧列表选择同一个房间）。
- 看服务端日志是否有 `first rtp packet`。
- UDP 被拦时，页面显示“已连接”但一直没有声音；设置里的诊断会显示码率 0。
- 确认没有开“闭音”（耳机图标）；麦克风按钮是否被静音。

## 想彻底没有警告？

三种做法，按省事程度排序：

1. **部署到有公网证书的服务器**（推荐长期用）
   用自己的域名 + Let's Encrypt，手机、朋友都不需要点警告。见 [腾讯云部署](腾讯云部署.md)。

2. **给局域网域名申请 DNS-01 证书**
   例如 `lan.kzblackx.net` 解析到 `192.168.5.139`，用阿里云 DNS 验证申请 Let's Encrypt 证书，再把证书路径填给 KzBlackX。这样局域网内也是受信任的 HTTPS。

3. **把自签证书装进设备信任库**
   把 `lan-cert/lan.crt` 装到手机/电脑的“受信任根证书”里。Android/iOS 对用户证书的限制较多，不如前两种省心。

## 一个提醒

局域网测试时不要加 `--public-ip`。那会让服务端把内网 IP 替换成公网 IP，局域网设备反而连不上媒体端口。只有部署在云服务器 NAT 后面时才需要 `--public-ip`。
